# 会员与积分计费规划

## 目标

增加会员注册、登录、积分购买、后台管理和生成次数按积分抵扣。积分余额与流水以服务端数据库为准，浏览器本地状态不能参与计费判断。

## 实施阶段

### 第一阶段：账号与钱包基础

- 邮箱注册、密码登录、JWT 鉴权和管理员角色。
- 用户积分余额与不可变积分流水。
- 管理员人工增加或扣减积分，支持幂等键。
- 积分套餐、充值订单、模型计价表的数据模型。
- Docker 内运行独立 Go + Gin + GORM 业务服务，nginx 同域转发 `/api/auth`、`/api/users`、`/api/wallet`、`/api/packages`、`/api/orders` 和 `/api/admin`。

### 第二阶段：会员前端与后台

- 注册、登录、退出和登录态恢复。
- 顶部账号入口、积分余额、积分流水与充值中心。
- 后台用户列表、状态管理、人工调账、套餐管理、订单查询和模型计价管理。
- 未登录用户仍可浏览；发起平台计费生成前必须登录。

### 第三阶段：支付

- 根据实际商户接入微信支付或支付宝当面付。
- 创建订单时固化套餐名称、积分和金额，后续套餐修改不影响历史订单。
- 支付回调必须验签，以支付平台交易号和订单号双重幂等。
- 只有服务端确认支付成功后，才能在同一事务中入账积分并写流水。

### 第四阶段：生成扣费

- 后台按模型和媒体类型维护单次积分价格，未启用的计价规则禁止平台计费生成。
- 创建生成请求时原子预扣积分并写 `generation_hold` 流水。
- 同步请求成功后结算；失败或取消时写相反金额的 `generation_refund` 流水。
- 异步视频任务在创建成功后保留预扣，任务最终失败时退款，成功时完成结算。
- 每次生成使用唯一幂等键，重试、刷新和回调不得重复扣费或退款。

## 安全边界

- 密码只存 bcrypt 哈希，JWT 密钥只从环境变量读取。
- 余额不能由前端传入或覆盖；管理员调账必须记录操作人和备注。
- 在线支付金额、套餐积分和模型价格均由服务端读取，不能信任前端值。
- 当前用户自有 API Key 的浏览器直连模式无法可靠计费；需要积分抵扣的生成必须统一经过服务端托管渠道。
- 管理接口必须同时验证登录态和管理员角色，后续增加操作审计与登录限流。

## 首版部署

当前单机部署默认使用 SQLite 数据库 `/data/business/c-aihuabu.db`，宿主机挂载 `./data/business`。正式开放支付或多实例部署前切换 PostgreSQL，并增加数据库备份、Redis 限流和任务队列。

## 随行付配置迁移

已从 `/Volumes/mac1/code/aiwebb/cang-ai` 提取随行付/天阙的协议实现和配置字段。源项目当前 `.env` 与 SQLite `site_settings` 未保存 `org_id`、`mno`、商户私钥或平台公钥的实际值，因此目标项目不会自动写入任何凭据。

目标项目使用 `C_AI_TIANQUE_ORG_ID`、`C_AI_TIANQUE_MNO`、`C_AI_TIANQUE_SUB_MECH_ID`、`C_AI_TIANQUE_PRIVATE_KEY`、`C_AI_TIANQUE_PUBLIC_KEY` 等服务端环境变量。启用前必须由管理员在服务器私密环境中配置，并将 `C_AI_TIANQUE_ENABLED=true`；密钥不能放入前端、Git 或文档。
